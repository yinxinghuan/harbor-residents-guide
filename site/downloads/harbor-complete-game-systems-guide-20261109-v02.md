# 海湾完整游戏系统与玩法说明

**既有生活玩法 Agent 与多人整合**

内部测试准备稿 · 修订版 2026-11-09 v0.2

**发布前草稿，非本次版本已上线功能清单。**

海湾是一款包含探索、生活、收集、任务与人物关系的像素 RPG。玩家可以沿着街区和海岸探索，在钓鱼、种植、交易与日常活动中获得资源，认识居民，并通过任务和共同经历改变人物关系与部分世界状态。

Agent 和多人是在这个既有世界上增加自主居民与共同参与，不是替代或删除钓鱼、种植等原有功能。开发上优先推进 Agent，不意味着产品介绍只剩 Agent。本次整合的重点，是让既有生活玩法、居民选择和真人参与逐渐落到一致、可追踪的世界规则中。

本文既说明已有游戏内容，也说明它们与 Agent、多人的整合方向。旧版本的发布或测试记录、候选版本的局部通过，都不能自动当作本次整合版本的验收结果。实际入口、启用系统、Agent 名单和可用动作，应以最终发布清单为准。

## 阅读状态说明

- **既有版本有证据**：旧版本的发布、玩法或测试记录支持该功能存在，不代表它已在本次整合版本重新验收。
- **候选已局部验证**：候选版本中某个明确流程通过短测，只覆盖被测环节，不扩大为整个系统或所有设备均已通过。
- **设计方向**：解释希望形成的玩法与规则，不代表该事件、动作或联动已经启用。
- **本次整合未验证**：尚未确认它在本次 Agent 与多人版本中的完整行为。没有验证，不等于功能不存在、不兼容或已经删除。

## 1 版本定位

真人玩家和有自主目标的 Agent 居民共同影响一个持续变化的海湾世界。真人决定自己想做什么；Agent 根据自身目标、已知信息和可用资源作出选择；世界规则判断行动是否成立，并记录结果。

既有探索和生活系统提供地点、资源、人物与长期目标。Agent 增加居民自身的需求和行动，多人能力则让不同参与者的行动落到同一世界状态，而非各自互不相关的存档。

本轮新增能力重点观察三件事：Agent 是否实际行动；玩家能否影响它的后续选择；共同结果是否能被其他参与者看见，并在重载后保留。与此同时，玩家仍应能够理解和体验发布清单中开放的旧玩法，而不是为了看 Agent 就忽略整个生活世界。

## 2 海湾的完整游戏系统

### 2.1 地图探索与通行

**玩家能做什么**：既有版本与玩法记录中出现过连续街区、场景往返，以及港口、海岸、居民庭院等地点。探索不只是看地图，也包括寻找人物、到达活动地点和发现路线变化。修桥、开放路线与集市已有源码或发布证据，说明任务结果可以影响部分通行条件。

**与多人和 Agent 如何关联**：整合目标是让真人与 Agent 对地点、桥梁是否修复、路线是否开放有一致认识。居民的行程和玩家的到达能力应受到同一套通行规则约束。多人共享地点与路况，不自动等于所有玩家都能实时看见彼此移动。

**当前证据边界**：连续街区在 10 月 19 日已有正式记录，地图验收在 10 月 24 日已关闭，本说明不重开已关闭的地图验收。10 月 31 日证据支持修桥、路线和集市内容。本次复用范围及共享路况仍需随整合版本确认，不能宣传实时同屏已完成，也不能承诺世界可无限自动扩图。

### 2.2 钓鱼与鱼获

**玩家能做什么**：既有钓鱼流程包括钓点交互、领取钓具、下竿与收线、确认鱼获、鱼获进入背包、购买鱼饵和查看鱼类图鉴，历史测试也涉及卖鱼。钓鱼既提供收集目标，也让玩家把一次操作转化为可保存、可使用的生活成果。具体按钮、开放水域与可钓鱼种范围以当前界面为准，不是任何水面都能钓鱼。

**与多人和 Agent 如何关联**：设计上，捕鱼成果可以成为居民订单、交易或合作中的材料。若鱼被卖给或交给另一位参与者，系统需要明确原持有人、接收方、数量与结算，避免同一条鱼重复交付或重复获得奖励。居民据此调整需求或后续计划，是希望打通的 Agent 联动，不是已启用承诺。

**当前证据边界**：10 月 22 日正式版本有钓获银鳞鱼的实测，包括未领取时重新进入仍保留、确认后进入背包、购买虫饵，以及刷新后鱼获和鱼饵保留；当时图鉴进度曾显示 1/12，该记录不等于本次鱼种上限。10 月 27 日另有新版钓鱼与关闭领具界面的正式替换记录，手机手感尚未验完。这些证据不能替代本次与 Agent、多人交易的完整联调。

### 2.3 种植与植物

**玩家能做什么**：既有种植内容包含罗勒和薄荷，相关流程包括领种、播种、浇水与收获，另有买种后库存变化的实录。植物成长为日常活动提供需要持续照料的目标，玩家可以在探索、照料与收获之间安排自己的节奏。

**与多人和 Agent 如何关联**：设计上，居民的材料需求可以形成采购、照料或交付合作。多人环境下，需要明确私人地块、公共作物和收获物的归属，以及谁可以照料或领取。这里是在说明需要明确的整合规则，不表示已经开放抢收或其他竞争机制。

**当前证据边界**：罗勒、薄荷种植在 10 月 19 日已有正式记录；11 月 6 日候选的领种、播种、浇水、收获与刷新保存曾通过短测。完整自然生长周期、生态效果和 Agent 经济联动并未因此全部验证。

### 2.4 时间昼夜与休息

**玩家能做什么**：自然时间已是既有世界的一部分，昼夜为环境和生活活动提供节奏；历史实录也包括回房小睡后时间变化。玩家可以把探索、照料、交谈和休息安排为一段连续的日常，而不只是完成互不相关的按钮操作。

**与多人和 Agent 如何关联**：11 月 2 日确立的规则方向是共享世界使用统一时钟，个人休息不改变其他玩家的公共时钟。Agent 的决策时段与世界时间需要对齐，个人休息和公共世界推进则要分开处理。旧版本的小睡表现不能直接照搬成多人世界的全局快进。

**当前证据边界**：10 月 19 日已有自然时间正式记录，10 月 30 日有回房小睡导致时间变化的实录。本次统一时钟、时间倍率及离线行为实际启用情况仍待核验，不能说一个人睡觉会让所有人的世界快进，也不能说无人在场时已经实现 24 小时持续运行。

### 2.5 天气与环境

**玩家能做什么**：晴雨等天气为街区和海岸带来不同的环境感受，也是玩家观察世界变化的一部分。既有版本有晴雨内容，候选版本还出现过从阴天转为小雨，并在刷新后保留的测试结果。

**与多人和 Agent 如何关联**：整合目标是让同一共享世界中的参与者面对一致的天气事实。居民根据天气调整活动，玩家因此改约、传递消息或选择不同活动，是可以形成的生活情境，仍需由具体规则和行动支持。

**当前证据边界**：晴雨在 10 月 19 日已有正式记录；11 月 6 日候选的阴天转小雨与刷新保存通过短测。完整自然天气周期、共享天气及其生态效果尚未全部确认。台风等扩展内容在本次版本中的状态未核，不承诺天气已会损坏作物或按特定概率改变产量。

### 2.6 动物观察与生态

**玩家能做什么**：动物增加了探索中的观察和收集内容。候选测试中有晒太阳的猫被登记后刷新仍保留记录的流程，既有记录也包括狗和螃蟹的动作。玩家可留意动物出现的位置和行为，并使用当前界面开放的观察与记录功能。

**与多人和 Agent 如何关联**：设计上，动物观察可以成为居民委托、消息或地方见闻的素材。例如玩家发现某种行为后向居民传达观察结果。是否形成共同记录、个人收藏或可交流的消息，应由明确规则决定。

**当前证据边界**：10 月 24 日已有狗与螃蟹动作记录，11 月 6 日候选的猫观察登记与刷新保存通过短测。动画和记录不等于完整的自主动物 AI；动态动物 AI 尚未全完，也不能默认所有动物都可以捕捉或养殖。

### 2.7 背包物品与图鉴

**玩家能做什么**：背包帮助玩家查看和保存已持有的鱼获、鱼饵、种子等物品；图鉴和观察记录保存发现与收集进度。鱼类图鉴有历史实测，观察条目也有刷新保留证据。这些记录让一次活动的结果在离开场景后仍有意义。

**与多人和 Agent 如何关联**：多人环境首先需要保证个人物品不串号，Agent 与真人之间的资源转移还要检查持有人、数量和接收对象。关系条目、观察条目与可以交易的物品并不是同一种数据，不能把“看见一条记录”直接当作“拥有一件可赠送物品”。

**当前证据边界**：鱼获、鱼饵、种子与部分观察记录已有保存或库存变化证据，但不代表所有素材库里的图片都已经是可拾取物品。本次背包与共享交易的一致性、跨端行为及所有类别的保存范围仍需按发布清单核验。

### 2.8 金钱商店与资源流转

**玩家能做什么**：买种、买鱼饵和卖鱼已有既有版本或测试记录。经济系统把一次生活活动的成果转化为下一次选择：购买所需物品，准备之后的活动，或者出售成果换取其他资源。资金、物品和劳动都有成本，而不只是对话里的数字。

**与多人和 Agent 如何关联**：Agent 自主买卖、提出或接受报价，以及与真人交易，是整合目标。资源不足、价格不合适或材料已有替代来源，都应有机会影响选择。多人交易还需要明确谁付钱、谁收货，以及一次行动只结算一次。

**当前证据边界**：历史隔离沙盘验证过部分赠送、交易和结算，但它与旧生活系统的商店测试是不同证据，不能合并成“本次共享经济已打通”。本次可用交易动作、Agent 自主买卖范围和共享数据库闭环仍待确认，不能承诺动态市场定价已经上线。

### 2.9 居民对话与人物关系

**玩家能做什么**：玩家通过交谈、共同经历与人物事件认识居民，推进关系并获得相应反馈或奖励。Mara、Avery、Samira、Owen 和 Dani 的五阶段关系内容已有历史正式记录。固定人物内容让玩家有机会连续了解一个人，而不是每次见面都从零开始。

**与多人和 Agent 如何关联**：既有关系内容与 Agent 的目标、事件和记忆可以共存，并不天然冲突。整合时应使用一致的经历与承诺记录，避免剧情系统和 Agent 各自写出矛盾结果。多人场景还要区分共同发生的事件、个人关系进度和不应向别人公开的信息。

**当前证据边界**：10 月 19 日已有前四位居民的关系正式记录，10 月 23 日补核到包含 Dani 的五位居民五阶段内容。这里不臆造阶段名称，也不表示所有角色或自主互动都已完成。本次固定关系与 Agent 记忆的联动、私人边界及真人影响仍需确认。

### 2.10 任务剧情与世界变化

**玩家能做什么**：既有任务提供明确目标和行动理由，包括“眼前的事”寻路修复发布记录、修桥后改变通行、开放路线与集市，以及人物事件、经历和承诺记录。玩家的行动可以影响部分场景状态，不只是完成一段对白。

**与多人和 Agent 如何关联**：原剧情继续提供明确目标，Agent 事件可以增加变化和新的参与机会，而不是自动替换全部原剧情。设计上，居民提出需求、玩家选择协助、不同参与者分工，再由完成结果影响下一步行动，可以形成合作或动态任务。

**当前证据边界**：10 月 31 日的源码与发布证据支持修桥、路线、集市、关系经历与承诺记录，以及种植收获等内容。受限的动态支线不等于无限生成任务，更不等于自动生成任何地图和建筑。具体合作链是否已接通，仍要看本次实际动作和验收结果。

### 2.11 精力休息日常节奏与训练

**玩家能做什么**：既有金钱、体力和背包规则可以支撑日常选择，休息与小睡让玩家在活动之间调整节奏。训练是存在过的独立模块，曾影响钓鱼准入；它与钓鱼、种植等生活玩法需要在当前界面中有清楚的关系。

**与多人和 Agent 如何关联**：整合时可以复用既有资源与体力约束，让行动有成本，但不能把个人恢复或休息直接变成对所有人的世界时间操作。训练及其他独立模块是否启用、是否仍影响某项活动，应明确列在本版范围中，而不是让玩家猜测隐藏门槛。

**当前证据边界**：休息旧机制和小睡时间变化有历史实录，训练不是本次发布重点。本文不宣称全局战斗改造已经完成，也不把旧训练条件自动当作本次钓鱼门槛；相关独立模块以本次发布清单为准。

### 2.12 身份存档与重新进入

**玩家能做什么**：个人身份、背包与关系等持久化有历史证据，鱼获、鱼饵、作物和部分观察记录也有重新进入或刷新后的检查。存档让玩家能够离开再回来，继续先前的生活，而不必把每次打开都当作新一局。

**与多人和 Agent 如何关联**：多人需要同时保存个人状态和共享事实，Agent 行动则需要留下可核对的事件与结果。重新进入后，个人仍应是同一个人，物品仍属于正确对象，共同事件也不应被重复执行或各自出现不同结局。

**当前证据边界**：已有单端或单个流程的保存结果，不等于双端一致、真实身份隔离和新共享读写已完整通过，也不等于旧存档一定能无损迁移。本次登录、测试账号、跨端、数据保留或清空规则需要单独明确。

## 3 Agent 增加怎样的体验

海湾以像素生活 RPG 呈现地图、居民、物品和生活活动。Agent 系统的目标是让居民不只等待固定对白，而有自己要办的事，并受材料、金钱、时间、消息及他人影响。

**设计例子**：某居民缺材料，无法完成工作；另一人虽有材料，却不接受原报价。玩家可以提供材料、传递消息、参与委托，或选择不介入。这个例子解释居民需求如何进入生活玩法，不代表某个具体事件已经在本版开放。

乐趣在于看懂谁想做什么、掌握什么消息、受到什么限制，以及帮助或拒绝怎样改变计划。原有钓鱼、种植、探索、人物关系与任务提供了可以发生这些变化的世界内容。

## 4 玩家怎样玩

**从自己的生活目标开始**：选择发布清单中开放的活动，例如探索一段街区、完成一次钓鱼、照料植物或认识一位居民。先看懂该活动的入口、资源和结果，不必先理解 Agent 的技术机制。

**先观察再介入**：选择一名居民或一条事件连续观察，关注其位置、需求、可用交互和事件记录。测试时只操作界面实际开放的动作。

**用实际行为影响世界**：赠送应产生归属变化，交付应有结算，承诺应写清对象与内容，不能只有文本成功。原有生活活动的产出能否用于这些行动，应由本版实际开放的联动决定。

**观察后果**：看下一轮行动是否利用新信息或资源，而不只看点击瞬间的提示。玩家也可以选择不介入，观察居民是否会采取其他可行做法。

**双账号核对**：两名测试者核对共同事件结果，同时确认背包、身份及私人信息不串号。多人不是默认共享所有个人收藏、物品和关系进度。

**重载后再看**：检查结果是否仍在，避免连续重复提交掩盖问题。尚不能预设本版已支持实时同屏移动、邀请房间或实时聊天，须以发布清单确认。

## 5 Agent 运作机制

**观察**：读取允许它知道的状态、资源、事件和记忆。设计上不是全知视角，不应自动知道别人的秘密。

**决策**：模型根据目标和条件选择程序提供的合法行动组合；规则层不是另一个 AI 模型。可选动作限制了自由度，既要测是否合法，也要测是否单调。

**执行**：模型说完成不等于完成，须检查资源、归属、身份、世界状态，以及是否重复执行。钓鱼、种植、商店和任务的旧规则不能仅凭一句模型文本就被绕过。

**记录**：结果形成事件和状态，供后续判断。历史隔离沙盘验证过部分真实模型行动、赠送、交易、合作和重载，但不能代替本版共享世界验证。

**回合设计**：原 v0.4 方案先设 6 名居民，再扩至 12 名；每日 4 个决策时段；每名 Agent 每时段最多 1 次决策、1 个主要行动和 1 条限额沟通；真人可在回合之间介入。这些是设计基准，本次实际人数、频率、额度尚待发布清单锁定，不得当作已启用配置。

## 6 多人和 Agent 的整合边界

多人能力支撑大家参与同一世界，但仍需区分三类信息：共同世界事实，例如开放路线和已完成的公共事件；个人状态，例如背包与关系进度；只允许特定对象知道的消息和记忆。共同参与，不等于所有内容都向所有人公开。

## 7 这些系统如何串起来

下面三段都是**设计示例，不是本版已启用事件或整条链已通过的证明**。旧玩法中已有证据的环节，与仍需整合的环节分别说明。

### 设计示例 A 从钓到一条鱼到改变居民计划

1. 玩家在已开放的钓点完成钓鱼，并确认鱼获进入自己的背包。**已有证据**：钓获、确认入背包及刷新保存有历史实测。
2. 某位居民出现对鱼的需求，玩家决定是否提出交易。**整合目标**：把实际鱼获与 Agent 的需求和允许交易的物品对应起来。
3. 玩家报价，居民根据资源和目标接受或拒绝。**整合目标**：使选择受到真实资源与规则约束，而非只有一段交易对白。
4. 双方交付与结算，鱼离开原持有人的背包，接收方取得鱼，资金按约定变化。**整合目标**：共享世界核对归属，并确保只结算一次。历史部分沙盘交易证据不等于这条鱼获交易链已接通。
5. 居民得到材料后调整下一轮计划，玩家能够从行动或事件中看到变化。**整合目标**：实际资源影响后续决策，而不是模型口头说已经改变。

钓鱼本身的存在与是否接入居民采购是两件事。尚未接入这条链，不代表钓鱼不能独立体验。

### 设计示例 B 从购种到公共工程改变通行

1. 玩家购买种子，背包库存发生变化。**已有证据**：历史实录有买种与库存变化。
2. 玩家播种、照料并收获。**已有证据**：既有种植内容和候选的领种、播种、浇水、收获、刷新保存短测；完整自然周期另有边界。
3. 玩家把收获物用于一项居民委托，或与其他参与者分工。**整合目标**：让需求、物品归属、交付和奖励形成明确规则。
4. 委托结果推进公共工程，工程完成后改变通行。**已有证据与待整合部分**：修桥及路线变化各自有旧证据，但没有因此证明“种植产出到委托再到公共工程”的整条链已接通。
5. 其他参与者和居民随后使用同一条开放路线。**整合目标**：公共工程的结果成为一致的共享世界事实。

这个例子说明生活产出怎样有机会影响世界，不表示所有作物都能用来修桥，也不表示任意文本委托都能自动改变地图。

### 设计示例 C 人物关系与天气共同影响安排

天开始下雨，某位居民调整原本的行程。玩家选择改约、传递消息，或先去做另一项生活活动。居民之后根据收到的信息和双方经历作出回应。

**已有证据**：天气与人物关系各有既有版本记录，部分候选天气变化也有保存短测。**整合目标**：让天气影响居民活动，让传达的消息进入后续判断，并维持正确的关系与私人信息边界。这是设计情境，不是某个雨天事件已经启用。

## 8 第一轮体验与测试路线

先体验已开放的生活玩法，再选择一条 Agent 互动观察。以下路线帮助理解版本，不是要求把全部旧玩法重新变成上线门槛；已经关闭的专项验收不因这份说明而重开。本次启用的整合改动与已知风险，才需要有针对性地核对。

### 1 认识世界与当前范围

从已确认的内测入口进入，记录版本、设备和时间。看当前发布清单开放了哪些场景、生活系统与 Agent，确认场景、人物和提示可见。沿一段地图走动，看看路线、活动地点和返回路径是否容易理解。

### 2 体验一项生活活动

在钓鱼、种植或其他实际开放的活动中选一项。钓鱼时核对鱼获确认与背包；种植时关注种子、照料和收获反馈。以当前界面开放的步骤为准，不要为了凑齐一条示例链而寻找尚未启用的功能。

### 3 看物品和人物如何留下记录

查看背包或图鉴中刚刚发生的变化，再与一位已开放人物交谈，了解关系、经历或任务反馈。注意区分可交易物品、观察条目和个人关系记录。旧玩法可以独立体验，不必每一步都先接入 Agent。

### 4 观察一名 Agent 并完成一次互动

选择本版启用的 Agent，观察它在做什么、需要什么。若看不懂，应记录现象，而非猜测后台正在运行。若界面实际开放赠送、交易或委托，选择一次操作，记录前后资源，核实状态变化，而不只看成功提示。

### 5 观察后续反应

观察下一轮是否使用新信息或资源。区分尚未到决策时段、未提交成功、没有反馈，或行为未受影响等现象。测试者只需保留过程，不必判断技术根因。

### 6 双账号对照

在本版实际开放的共同事件上核对结果是否一致，同时检查私人边界，确认背包、身份和私人信息没有串号。不要求两人共享所有关系与收藏，也不把实时同屏当作默认能力。

### 7 重新进入

核对身份、资源、记录和行动结果是否保留。结果不明时，不要连续重复点击。若发布清单说明会清空测试数据，应按该规则判断，而不是把预期清空与存档缺陷混在一起。

## 9 反馈重点与模板

**生活玩法清楚**：地图与活动入口是否容易找到？钓鱼、种植等实际开放流程是否可理解？获得的物品、消耗的资源和保存的记录能否看见？

**行为可信**：Agent 有没有目的？会不会响应资源不足、拒绝和新消息？是否重复无意义动作？是否宣称了没有发生的结果？

**玩家影响力**：介入机会是否明确？结果是否可见？不同选择有区别吗？是否只能围观？既有生活成果能用于哪些实际开放的互动？

**世界一致**：共同事件是否一致？有没有串号或泄露？有没有重复扣款、重复发奖或重载后丢失？个人与公共状态是否被混淆？

**体验清楚**：下一步是否明确？能否区分等待下一轮与卡住？手机上的遮挡、滚动和点击是否正常？事件和人物关系的反馈是否充分？
